================================================================================
9 - HIGH - The default seeder creates an administrator with the password "password"
================================================================================
Status        : FIXED (2026-09-20) - see "FIX APPLIED" at the end of this file
Category      : Use of hard-coded credentials - OWASP A07:2021
Verified      : Seeder read directly; MockUserSeeder is wired into DatabaseSeeder
Affected files: database/seeders/DatabaseSeeder.php:15-21
                database/seeders/MockUserSeeder.php:15, 20-42, 56-72

--------------------------------------------------------------------------------
SUMMARY
--------------------------------------------------------------------------------
`DatabaseSeeder` - the seeder that `php artisan db:seed` and
`migrate --seed` run by default - calls MockUserSeeder unconditionally:

    public function run(): void
    {
        $this->call([
            PlanSeeder::class,
            MockUserSeeder::class,     // <-- no environment guard
        ]);
    }

MockUserSeeder creates three accounts with a constant password and marks the
first as an administrator:

    public const PASSWORD = 'password';

    ['name' => 'Admin', 'email' => 'admin@example.com', 'is_admin' => true,
     'plan' => 'enterprise', ...]

    User::updateOrCreate(['email' => $account['email']], [
        'password'          => self::PASSWORD,
        'email_verified_at' => now(),
        'is_admin'          => $account['is_admin'] ?? false,
        ...
    ]);

Note `updateOrCreate`: re-running the seeder **resets** the password of an
existing `admin@example.com` back to `password`, so an operator who rotated it
loses that change on the next seed.

PlanSeeder is genuinely required in every environment (the plans table drives
billing), so operators have a legitimate reason to run `db:seed` in production -
and doing so silently creates the admin backdoor.

--------------------------------------------------------------------------------
IMPACT
--------------------------------------------------------------------------------
* A known-credential administrator account on any environment that has been
  seeded: admin@example.com / password. The admin dashboard can promote users to
  admin and delete accounts, so this is a complete compromise of the instance and
  of every tenant's data.
* `admin@example.com` is among the first addresses any credential-stuffing or
  scanning tool tries, and `password` among the first passwords.
* The accounts are created pre-verified (`email_verified_at => now()`), so no
  mail loop stands in the way.
* Combined with finding 8, they are also the exact accounts reachable through the
  password-free quick-login button.

--------------------------------------------------------------------------------
PROPOSED FIX
--------------------------------------------------------------------------------
(1) Separate "required reference data" from "demo data"
    [database/seeders/DatabaseSeeder.php]

        public function run(): void
        {
            $this->call(PlanSeeder::class);      // always needed

            if (app()->environment('local', 'testing')) {
                $this->call(MockUserSeeder::class);
            }
        }

    Production seeding now gets the plans it needs and nothing else.

(2) Refuse to run the mock seeder anywhere else, whatever invokes it
    [database/seeders/MockUserSeeder.php]

        public function run(): void
        {
            if (! app()->environment('local', 'testing')) {
                throw new \RuntimeException('MockUserSeeder must not run outside local/testing.');
            }

            foreach (self::accounts() as $account) {
                $this->seedAccount($account);
            }
        }

    A developer can still call `db:seed --class=MockUserSeeder` directly; this is
    what stops that on a production host.

(3) Stop resetting existing passwords. Use `firstOrCreate` for the password, or
    only set it when the record is newly created, so an operator's rotation is not
    undone by a later seed run.

(4) Do not hard-code the password even locally. Read it from the environment with
    a local-only default:

        public static function password(): string
        {
            return env('MOCK_USER_PASSWORD', 'password');
        }

(5) Remediate existing deployments. On every environment:

        php artisan tinker --execute="dd(App\Models\User::whereIn('email',
            ['admin@example.com','test@example.com','demo@example.com'])->get(['id','email','is_admin']));"

    Delete these accounts if present, and audit for anything they created or
    changed. If the account existed, treat the instance as compromised until
    proven otherwise: rotate APP_KEY, session data, Stripe keys and database
    credentials.

================================================================================
FIX APPLIED (2026-09-20)
================================================================================
DatabaseSeeder calls PlanSeeder always and MockUserSeeder only in local/testing.
MockUserSeeder::run() throws if invoked anywhere else, so
`db:seed --class=MockUserSeeder` on a production host fails. seedAccount() now
uses firstOrNew and only sets the password when creating the record, so a rotated
password is no longer reset by a later seed run; the value can be overridden with
MOCK_USER_PASSWORD.

STILL REQUIRED (operational, cannot be done from here): check every deployed
environment for admin@example.com, test@example.com and demo@example.com and
delete them if present. If the admin account existed on a public host, treat that
host as compromised rather than merely patched.

Files: database/seeders/DatabaseSeeder.php, database/seeders/MockUserSeeder.php
Tests: tests/Feature/Security/AuthHardeningTest.php

Full suite after the change: 130 passed (367 assertions).
